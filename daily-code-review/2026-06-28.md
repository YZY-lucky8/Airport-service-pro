## 领先分支代码审查

### 1. `yangziyu/rate-limit`（领先 2 提交）

**变更范围**: `backend/app.js` (+781/-7), `public` (gitlink)

**提交列表**:
- `394aa14` 修改静态文件路径为相对路径
- `b056e3b` 修复app.js

**关键变更与安全审查**:

1. **BloomFilter IP 黑名单** ⚠️ 中风险
   - 实现了一个原生布隆过滤器用于 IP 黑名单拦截
   - 问题: 布隆过滤器存在误报（false positive），合法 IP 可能被错误拦截
   - 问题: 黑名单硬编码在代码中（`bannedIPs` 数组），生产环境应改为数据库配置
   - 问题: `_hash1`/`_hash2` 使用简单 DJB2 变体，碰撞风险较高

2. **滑动窗口频率检测** 🔴 高风险
   - `requestCounts` Map 存储所有 IP 请求时间戳，**内存泄漏风险** — 无淘汰机制清理空闲 IP
   - 限制为 1秒5请求，对正常 API 调用可能过于严格
   - `pool.execute()` 异步写入攻击日志使用了 `.catch()`，但外层又包裹了 try-catch，冗余

3. **攻击监控中间件** `attackMonitor` ⚠️ 中风险
   - 与滑动窗口限流功能重复，存在双重限流
   - `failedAttempts` 和 `rateLimit` Map 均为内存存储，重启即丢失
   - `setInterval` 清理周期合理（5分钟），但 Map 在长时间运行后仍可能内存增长

4. **HMAC 令牌机制** ⚠️ 中风险
   - 依赖 `process.env.HMAC_SECRET`，若未配置将使用 `undefined` 作为密钥（严重安全隐患）
   - `TOKEN_TTL` 默认 300 秒，但无环境变量时的行为未明确

5. **`trust proxy: true`** ⚠️ 中风险
   - 设置信任所有代理，在直接暴露的环境中可能被 X-Forwarded-For 绕过

6. **`require('dotenv').config()` 重复调用** — 在文件中出现了两次
