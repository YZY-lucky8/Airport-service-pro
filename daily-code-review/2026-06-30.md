## 3. 代码审查 — 安全问题 🔴

### 3.1 硬编码数据库密码 — 严重 ⚠️⚠️⚠️

**涉及文件**: `backend/routes/security.js`（段琼馨/前后端 分支）

```javascript
// 第 22 行
password: 'Airport123!',   // 修改为你的密码
```

**风险**: 密码明文硬编码在路由文件中。即使 `app.js` 中使用了 `process.env.DB_PASSWORD`，`security.js` 的 fallback 连接池仍使用硬编码密码。如果此文件被提交到 Git 仓库，任何人克隆仓库即可获取数据库密码。

**建议**: 统一从环境变量读取密码，`security.js` 中不应有自己的数据库连接配置。

### 3.2 硬编码 admin 登录凭据 — 严重 ⚠️⚠️⚠️

**涉及文件**: `backend/routes/security.js`（段琼馨/前后端 分支）

```javascript
// 第 983-985 行
const { username, password } = req.body;
if (username === 'admin' && password === 'admin') {
```

**风险**: 管理员登录使用 `admin/admin` 硬编码凭据。这是一个已知的高危凭据组合，容易被暴力破解或社会工程攻击利用。同时没有速率限制保护此登录接口。

**建议**: 
- 使用数据库存储哈希后的密码
- 使用 JWT / session 认证机制
- 为登录接口添加速率限制

## 4. 代码审查 — 潜在 Bug / 逻辑问题 🟡

### 4.1 布隆过滤器误判风险

**涉及文件**: `backend/app.js`（王晓恩添加的 BloomFilter）

- 布隆过滤器存在 **误判（false positive）** 概率。即使配置为 0.001 错误率，对于 10000 个黑名单 IP，平均会有 **10 个正常 IP 被误拦截**
- 无删除机制，一旦 IP 被加入黑名单无法移除
- 黑名单包含 `::1` 和 `::ffff:127.0.0.1`（IPv6 localhost），可能影响本地测试

**建议**: 生产环境建议改用 Redis Set 或数据库表做精确黑名单匹配

### 4.2 速率限制过于激进

**涉及文件**: `backend/app.js`（杨梓瑜添加的滑动窗口）

```javascript
const RATE_LIMIT_WINDOW_MS = 1000;    // 1 秒
const RATE_LIMIT_MAX_REQUESTS = 5;    // 5 次
```

- 1 秒 5 次请求对 SPA 前端（多个 API 调用、静态资源）来说 **极其严格**
- 单个页面加载可能触发 10+ 个请求，用户访问一次就会被封禁
- `requestCounts` Map 没有内存清理上限，长期运行可能导致内存泄漏

**建议**: 提高阈值（如 60 秒/100 次）或按路径分类限制

### 4.3 内存泄漏风险 — 攻击监控 Map

**涉及文件**: `backend/app.js`（段琼馨/前后端 分支）

- `attackMonitor.failedAttempts` 和 `attackMonitor.rateLimit` 是全局 Map
- 虽然有 10 分钟过期清理，但在高流量场景下 Map 会持续增长
- 建议添加最大条目数限制

### 4.4 未解决的冲突标记残留

**涉及文件**: `backend/app.js`（段琼馨/前后端 分支）

- 7 组 `<<<<<<< HEAD` / `=======` / `>>>>>>>` 冲突标记
- 这将导致 **语法错误**，Node.js 无法解析该文件

