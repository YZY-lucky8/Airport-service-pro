## 🔎 代码审查发现

### 🔴 严重安全问题

#### 1. 硬编码数据库密码（多处）

**位置：** `backend/app.js`（yangziyu/rate-limit 分支，L95）
```javascript
password: 'Airport123!',   // 请改为你的真实密码
```

**位置：** `backend/routes/security.js`（段琼馨/前后端分支，L22）
```javascript
password: 'Airport123!',   // 修改为你的密码
```

**位置：** `database/TEST.sql`（段琼馨/前后端分支，L5）
```sql
CREATE USER 'project_user'@'localhost' IDENTIFIED BY 'Airport123!';
```

**风险：** 密码硬编码在代码仓库中，任何有仓库访问权限的人都能获取数据库凭证。一旦代码泄露或部署到生产环境，将导致数据库被入侵。

**建议：** 使用环境变量（`process.env.DB_PASSWORD`）或密钥管理服务。

#### 2. 硬编码管理员凭据

**位置：** `backend/routes/security.js`（段琼馨/前后端分支，L983-985）
```javascript
if (username === 'admin' && password === 'admin') {
```

**风险：** 管理员账号密码为 `admin/admin`，这是最常见弱密码组合，任何攻击者都能直接登录管理后台。

**建议：** 使用数据库中的用户表验证，至少应使用哈希后的密码。

#### 3. 硬编码 HMAC Secret

**位置：** `backend/app.js`（yangziyu/rate-limit 分支）

虽然使用了 `process.env.HMAC_SECRET`，但在 `backend/app.js` 第 93 行有 `require('dotenv').config()` 重复调用。如果 `.env` 文件被提交到仓库或 `HMAC_SECRET` 有默认值，令牌系统将被攻破。

**建议：** 确认 `.env` 在 `.gitignore` 中；为 `HMAC_SECRET` 设置强默认值或使用密钥管理。

### 🟠 中等风险问题

#### 4. 内存泄露 — 速率限制 Map 无上限清理

**位置：** `backend/app.js`（yangziyu/rate-limit 分支，L123-145）
```javascript
const requestCounts = new Map();
// ... 没有清理逻辑
```

滑动窗口限流的 `requestCounts` Map 只添加不删除。对于长时间运行的服务，每个访问过服务器的 IP 都会留一条记录，最终导致内存泄露。

**建议：** 定期清理 Map，或改用 TTL 缓存（如 `node-cache`）。

#### 5. 速率限制过于严格

**位置：** `backend/app.js`（yangziyu/rate-limit 分支，L120-121）
```javascript
const RATE_LIMIT_WINDOW_MS = 1000;
const RATE_LIMIT_MAX_REQUESTS = 5;
```

**风险：** 1 秒内最多 5 个请求。对于正常用户（一个页面加载可能发送 10+ 请求），这会导致大量误拦截。

**建议：** 调整为 10-20 请求/秒，或按端点分别设置。

#### 6. 重复中间件 — 多层速率限制

**位置：** `backend/app.js`（yangziyu/rate-limit 分支）

- 第 123-155 行：滑动窗口限流中间件
- 第 240-260 行：`attackMonitor.checkRateLimit()` 中间件

两层独立的速率限制中间件，使用不同的算法和阈值。增加了复杂度和不一致行为的风险。

**建议：** 合并为统一的速率限制中间件。

#### 7. Bloom 过滤器误判

**位置：** `backend/app.js`（yangziyu/rate-limit 分支，L17-45）

黑名单 Bloom 过滤器配置为 10000 容量，误判率 0.001。虽然设置了 `trust proxy: true`，但 Bloom 过滤器有假阳性（false positive），可能误拦合法 IP。且当前黑名单包含 `127.0.0.2`、`::1` 等本地地址，可能影响开发环境。

**建议：** 生产环境使用数据库/Redis 存储黑名单，而非内存 Bloom。

#### 8. 模拟数据用于生产 API

**位置：** `backend/routes/security.js`（段琼馨/前后端分支）

`/api/security/intercept-trend` 和 `/api/security/defense-distribution` 返回硬编码模拟数据，注释写明了"简化版本"。这些数据会误导安全监控。

**建议：** 确保这些接口明确标记为测试/演示数据，或在生产环境连接真实数据源。

#### 9. SQL 注入风险（低风险）

**位置：** `backend/app.js`（yangziyu/rate-limit 分支）

大部分查询使用了参数化查询（`pool.execute(sql, [params])`），这是正确的。但需确认所有动态 SQL 都使用参数绑定。

**审查结果：** 本次审查的范围内未发现明显的 SQL 注入漏洞。✅

#### 10. 循环依赖风险

**位置：** `backend/routes/security.js`（段琼馨/前后端分支，L18-20）
```javascript
const app = require('../app');
var pool = app.pool;
```

`routes/security.js` require 了 `app.js`，而 `app.js` 可能 require 了 `routes/security.js`，形成循环依赖。虽然有 try-catch 兜底，但可能导致 pool 为 undefined。

**建议：** 将数据库连接池提取到独立的 `db.js` 模块。
