1. **硬编码测试 IP 黑名单泄漏内部网络信息**
   - `backend/app.js` 中包含明文测试 IP（`192.168.1.100`, `10.0.0.5` 等），上线前应移除或改为数据库/配置文件加载
   - 布隆过滤器虽然安全，但硬编码 IP 列表暴露了网络拓扑

2. **`express.static` 路径配置可能暴露敏感文件**
   - `app.use(express.static(path.join(__dirname, '../frontend')))` — 需确认 frontend 目录不包含 `.env`、`.git` 等敏感文件

3. **rate limit 中间件使用内存 Map，无持久化**
   - `requestCounts` Map 仅存于内存，进程重启后丢失，无法跨重启追踪攻击者
   - 大量唯一 IP 可导致内存泄漏（Map 只增不减，虽然清理过期时间戳但不删除空数组）

#### 🟡 逻辑问题

1. **Rate limit 过于严格**: 1秒内最多5个请求，可能误伤正常用户（尤其移动端弱网环境下重连）
2. **IP 获取依赖 `trust proxy`**: 若反向代理未正确配置 `X-Forwarded-For`，可能导致 IP 获取错误

   - 明文密码直接写在代码中，已推送到远程仓库
   - **建议立即修改数据库密码，并使用环境变量/配置文件管理凭据**

2. **硬编码 HMAC 密钥**
   ```sql

   ```
   - 默认密钥直接写在 SQL 建表脚本中
   - 任何人获取仓库即可伪造 HMAC 令牌

3. **硬编码管理员凭据** ⚠️⚠️

   - 管理后台使用 `admin/admin` 作为默认凭据
   - 无密码复杂度校验，无登录失败锁定

4. **大量模拟数据/占位数据**

2. **SQL 注入防护**: 大部分查询使用了参数化查询（`pool.query`），但需确认所有动态 SQL 都正确转义
3. **无 CSRF 保护**: 安全面板的 POST 接口（如 `hmac/rotate-secret`）未见 CSRF token 验证

2. **数据库连接双重配置**: 先尝试从 app.js 导入 pool，失败后再创建自己的连接池，增加了维护复杂度
