## 四、代码安全审查（重点文件）

### 🔴 严重问题

#### 1. 分支文件中有合并冲突标记未清理
- `段琼馨/前后端/backend/app.js`: **52 处** `<<<<<<<`/`=======`/`>>>>>>>` 冲突标记
- `yangziyu/rate-limit/backend/app.js`: **27 处** 冲突标记
- **风险**: 含冲突标记的代码直接运行会导致语法错误，服务无法启动

#### 2. 硬编码数据库密码
- `backend/routes/security.js` 中直接硬编码:
  ```js
  password: 'Airport123!',   // 修改为你的密码
  database: 'airport_db',
  ```
- `backend/app.js` 中虽然有环境变量回退，但默认密码仍是 `'Airport123!'`
- **风险**: 密码泄露， Anyone 读取代码即可连接数据库

#### 3. BloomFilter 误报导致合法 IP 被拦截
- 黑名单中包含 `127.0.0.2`、`::1`、`::ffff:127.0.0.1` 等本地回环地址
- **风险**: 开发/测试环境中所有本地请求被 403 拦截

#### 4. 速率限制过于严格
- 配置: 1 秒最多 5 个请求
- 在正常页面加载（多资源请求）场景下，一个页面请求就可能超过 5 次
- **风险**: 正常用户被误封，体验极差

### 🟡 中等问题

#### 5. 内存泄漏风险 — 滑动窗口 Map 无上限
```js
const requestCounts = new Map();
// 只清理过期条目，但不限制 Map 大小
```
长时间运行后，Map 会持续增长。应定期清理或使用 TTL Map。

#### 6. 攻击监控 Map 同样存在内存泄漏
```js
failedAttempts: new Map(),
rateLimit: new Map(),
```
虽然有 10 分钟过期清理，但没有设置最大条目数上限。

#### 7. `backend/routes/security.js` 中 `require('../app')` 循环依赖
```js
const app = require('../app');
var pool = app.pool;
```
这是不安全的模块加载方式，`app.js` 可能还未完全初始化。

#### 8. `sendError` 函数泄露内部错误信息
```js
function sendError(res, error, status = 500) {
  res.status(status).json({ success: false, error: error.message || error });
}
```
将 `error.message` 直接返回给客户端，可能泄露技术细节。

#### 9. 部分安全接口返回模拟数据
`intercept-trend` 接口硬编码模拟数据:
```js
const rateLimitData = [45, 32, 28, 45, 89, 156, 134, 167, 189, 145, 98, 56];
```
这会使安全监控面板显示虚假数据。

#### 10. HMAC 令牌时钟偏移容忍度过大
```js
if (timestamp > now + 300) // 允许5分钟的时钟偏移
```
5 分钟偏移窗口可能被用于重放攻击。建议缩小到 30-60 秒。

### 🟢 良好实践

- ✅ 使用参数化查询 (`pool.execute(sql, [params])`) 防 SQL 注入
- ✅ HMAC 令牌使用 `crypto.timingSafeEqual` 防时序攻击
- ✅ 添加了输入验证中间件 `validateInput`
- ✅ 使用可选链 `?.` 避免 null 引用崩溃
- ✅ `req.body || {}` 防御空 body
- ✅ 异步攻击日志记录不阻塞主请求
