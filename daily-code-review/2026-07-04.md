## 三、未合并分支代码审查

### 1. `yangziyu/rate-limit`（2 个未合并提交）

**变更范围**: `backend/app.js` (+781/-7), `public` (symlink)

**主要变更**:
- 新增原生 BloomFilter 类（IP 黑名单）
- 新增滑动窗口频率检测中间件（1秒内最多5请求）
- 新增攻击监控中间件
- 新增 HMAC 令牌系统（generate/verify）
- 新增输入验证中间件 `validateInput`
- 静态文件路径改为相对路径 `path.join(__dirname, '../frontend')`

**⚠️ 安全问题**:
1. **硬编码黑名单 IP 包含回环地址**: `127.0.0.2`, `::1`, `::ffff:127.0.0.1` — 在生产环境会把本地请求全部拦截 ❌
2. **BloomFilter 误判率风险**: `errorRate=0.001` 看似很小，但未实现过期/删除机制，误判的 IP 无法恢复 ❌
3. **内存泄露风险**: `requestCounts = new Map()` 永久保存每个 IP 的时间戳数组，缺少定期清理（只删除了超时的时间戳，但没有删除空数组的 key）❌
4. **硬编码密码**: 数据库密码 `'Airport123!'` 明文写在代码中 ❌
5. **`trust proxy: true` 不设白名单**: 任何伪造的 X-Forwarded-For 头都能绕过 IP 检查 ❌

**🐛 逻辑 Bug**:
1. **频率检测中间件没有异步化**: `pool.execute()` 虽然 `.catch()` 了，但如果 DB 连接失败会导致异常堆栈泄漏
2. **`BloomFilter._hash2` 使用 DJB2 算法但与 `_hash1` 区别不够大**: 可能导致位碰撞率高

**📋 建议**:
- 黑名单 IP 应来自数据库或环境变量
- 增加 Map 的定期清理定时器
- `trust proxy` 应指定可信代理 IP
