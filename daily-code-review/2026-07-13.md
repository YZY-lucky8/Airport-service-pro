## 4. 🔴 代码审查 — 安全与质量问题

### P0 — 严重安全漏洞

1. **硬编码数据库密码** — `backend/routes/security.js` 第14行
   ```js
   password: 'Airport123!',   // 明文密码
   ```
   **风险**: 任何人克隆仓库即可获取数据库凭据。
   **建议**: 使用 `process.env.DB_PASSWORD`，添加 `.env` 到 `.gitignore`。

2. **分支残留未解决的合并冲突标记** — `段琼馨/前后端` 的 `backend/app.js`
   ```
   <<<<<<< HEAD
   const crypto = require('crypto');
   =======
   // ==================== 王晓恩添加位置...
   >>>>>>> 940c284...
   ```
   **风险**: 冲突标记直接留在代码中，会导致运行时语法错误且可能引入逻辑分支差异。
   **建议**: 手动解决冲突后再提交。

3. **BloomFilter 哈希函数碰撞风险** — `backend/app.js`
   哈希函数使用简单位移+字符码，对抗性攻击者可构造碰撞。
   **建议**: 使用 `crypto.createHash()` 或成熟的 BloomFilter 库。

### P1 — 中等风险

4. **内存泄漏风险** — 滑动窗口限流的 `requestCounts` Map
   `requestCounts` 使用 `Map` 存储每个 IP 的时间戳数组，但仅在新请求时清理过期项。如果某个 IP 长时间不请求，其数据永远不释放。
   **建议**: 添加定期清理定时任务，或使用 TTL Map。

5. **速率限制过于严格** — 1秒/5请求
   对于正常用户（尤其是页面加载含多个资源请求），1秒5次请求很容易被触发。
   **建议**: 提高阈值（如1秒20请求）或按路径分类限流。

6. **循环依赖风险** — `backend/routes/security.js` 中 `require('../app')`
   ```js
   const app = require('../app');
   var pool = app.pool;
   ```
   `app.js` 中又 `require('./routes/security')`，存在循环依赖，pool 可能为 `undefined`。
   **建议**: 将数据库连接池提取到独立模块，或传入 pool 作为参数。

7. **安全路由使用模拟数据** — `/api/security/intercept-trend`
   直接返回硬编码数组而非查询数据库。
   **建议**: 标记为 TODO，尽快接入真实数据。
