### 🔒 安全审查

#### ✅ 积极方面
1. **密钥管理**: 使用环境变量 `process.env.DEEPSEEK_API_KEY` 存储密钥 ✅
2. **API 基址**: 使用 `baseURL` 允许自定义端点，避免硬编码 ✅
3. **超时控制**: 设置 `timeout: 7000` 防止永久阻塞 ✅
4. **重试限制**: `maxRetries: 0` 避免无限重试 ✅
5. **回退机制**: API 失败时返回静态默认消息 ✅

#### ⚠️ 潜在风险
1. **OpenAI SDK 引入**: 新依赖 `openai@^7.4.0`，需确保依赖来源可信
2. **API 调用暴露**: DeepSeek 的 system prompt 包含在客户端代码中，可能泄露系统指令
3. **公共 API 端点**: 使用 `https://api.deepseek.com` 公开地址，虽易变但不致命

#### 🔍 代码逻辑审查
- **意图分类前置**: 在 `processRequest` 中先进行 `GUARDRAIL_CHECK` 和 `INTENT_CLASSIFY`，符合安全设计 ✅
- **权限白名单**: `ALLOWED_ACTIONS` Set 定义明确，防止未授权动作 ✅
- **错误处理**: 对外返回通用错误消息，避免泄露内部细节 ✅
- **数据库操作**: 所有 SQL 使用参数化查询，防止 SQL 注入 ✅

#### 💡 改进建议
1. **Prompt 防护**: 将 system prompt 提取到环境变量或单独配置文件中避免硬编码
2. **API 密钥轮换**: 建议实现密钥轮换机制
3. **监控告警**: 增加 API 调用失败率监控
4. **速率限制**: 在 `app.js` 中增加 rate limiting 防止 API 滥用
